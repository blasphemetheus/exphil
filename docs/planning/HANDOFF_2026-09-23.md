## 3. R2: what passed and why it nearly didn't

The gate is held-out explained variance > 0.3 for a value head on the frozen
trunk's per-frame features (`ExPhil.Sim.Critic`, reward = stock differential +
0.01 × damage differential, gamma 0.995).

| run | data | result |
| --- | --- | --- |
| `v1` as first written | 4 rounds × 64 envs × 1800 f | train EV 0.913, **held-out 0.037** |
| `v1` refit, regularized | same data | test EV 0.25 (all 12 configs 0.20–0.26) |
| `v2` refit, regularized | **12 rounds** | **test EV 0.314 — PASSED** |

Three things mattered, in order:

1. **Early stopping.** The first fit peaked at validation EV 0.242 on epoch 1
   and decayed to 0.037 by epoch 60. `Critic.fit/4` now keeps the
   best-validation epoch and never selects on the test split (`fit/3` still
   exists for the smoke path and aliases val to test).
2. **Game diversity, not more frames.** Stride-6 subsampling (38k states)
   scored the same as every frame (230k states), so correlated neighbouring
   frames add nothing; going from 2 to 10 training rounds is what moved EV
   from 0.25 to 0.31.
3. Weight decay and dropout help marginally; the spread across all 12 configs
   at 12 rounds is 0.29–0.32, so the result is not a lucky configuration.

**The overnight loss:** the 12-round collection finished at 03:35 and then
crashed in its own fitting step because `critic_r2.exs` printed `h.ev_test`
after I renamed the history key to `ev_val`. The 2.7 GB of rollouts survived,
so the refit took two minutes this morning. Fixed in `80393602`.

Use `eval_runs/0923_r2/refit_v2/critic_best.bin` as the PPO critic init; it
carries `%{params, d: 512, hidden: 256, ev: 0.314}`.

## 5. The PPO blocker — everything known

**Design** (`lib/exphil/sim/ppo.ex`, `scripts/ppo_r3.exs`): train only the
6-component autoregressive head; the GRU trunk is frozen and never in the
graph, because the rollout already produced per-frame trunk features. The head
is rebuilt standalone on `Axon.input("trunk", {nil, 512})` via
`Heads.build_autoregressive_head/2`, whose **teacher-forced** inputs give the
conditional logits of all six components in one forward over stored
`(features, action)`. Three param sets: theta (training), the collecting
params (PPO ratio), the frozen prior (KL anchor). Loss = clipped surrogate +
`kl_coef`·KL(prior‖theta) − `ent_coef`·H. Critic = the R2 MLP, updated online.
Agent support is committed: `return_sample: true` on
`batch_get_controllers` (features + sampled bucket indices) and
`Agent.put_head_params/2` (swap `ar_*` in place, no reload).

**The failure**, reproducible in ~90 s:

```
devenv shell -- mix run scripts/ppo_r3.exs \
  --policy checkpoints/fox_v3_1_step8_mix4/model_best_policy.bin \
  --critic eval_runs/0923_r2/refit_v2/critic_best.bin \
  --envs 8 --frames 60 --iters 1 --epochs 1 --minibatch 480 \
  --out eval_runs/0923_ppo/smoke
```

```
** (Protocol.UndefinedError) protocol Nx.LazyContainer not implemented for type Atom
Got value:  nil
    (nx) Nx.Defn.Compiler.to_lazy_params/2
    lib/exphil/sim/ppo.ex:323: ExPhil.Sim.PPO.update_step/6   # grad_fn.(params, batch)
    scripts/ppo_r3.exs:146
```

Rollout, GAE, critic values and both eager `logits_of` calls all succeed — the
crash is the **first** `grad_fn.(params, batch)`.

**What is already ruled out** (all verified today, probes in the scratchpad
`/tmp/claude-1000/-home-blewf-git-exphil/4279adaa-.../scratchpad/jit2.exs`,
`jit3.exs` — recreate if /tmp was cleared):

- `params` is a plain map of `"ar_*" => %{"kernel"|"bias" => tensor}`; it and
  the batch both pass `PPO.check_tensors!/2`, a recursive walk that raises on
  any non-tensor leaf. Neither contains nil.
- With synthetic tensors of identical shapes, all of these work: jit on params
  alone, jit on the batch alone, jit on both, jit through `PPO.predict`, and
  `value_and_grad` through the head — including with the real `prior_logits`
  6-tuple in the batch.
- `Axon.ModelState` was removed from the jit boundary (its `:parameters` field
  holds nils); params now travel as bare maps and become a ModelState only
  inside the graph via `PPO.predict/3`. The error survived that change.
- Backends are normalized with `PPO.to_backend/2` (checkpoints and agent
  features arrive on `Nx.BinaryBackend`; that mismatch caused an earlier,
  different error and is fixed).

**Recommended next step**, in order:

1. Bypass container traversal entirely: change `grad_fn` to take flat
   positional tensor arguments (`fn p, feats, btn, mx, my, cx, cy, sh, adv,
   logp_old, pb, pmx, pmy, pcx, pcy, psh -> …`) and reassemble the maps inside
   the function. Verbose but eliminates the only untested surface.
2. If it persists, `IO.inspect` the real batch and params with
   `structs: false, limit: :infinity` at the call site and diff against the
   synthetic ones from `jit3.exs`, which provably work.
3. Sanity-check the agent's returned action map at runtime
   (`s.action` keys and shapes in `PPO.collect/6`) — it is the one input built
   by code paths the probes did not exercise.

Once it runs: smoke with `--envs 8 --frames 60 --iters 2`, confirm KL stays
small and `clip_frac` is non-zero, then the real run is
`--envs 64 --frames 600 --iters 200`, which checkpoints the head every 10
iterations and trips at `--kl-stop` (default 0.5).

## 6. Gotchas (unchanged ones are in HANDOFF_2026-09-22a §5)

- **`systemd-run --user` starts in `$HOME`.** Always launch long jobs with
  `scripts/launch_unit.sh UNIT 'mix run …'`, which cds inside the unit and
  tails the log. This bit four times on 09-22.
- **One EXLA process on the GPU at a time**; two agents at once produced a
  cuBLAS OOM. `EXLA_MEMORY_FRACTION` exists (config/runtime.exs) but is
  untested for co-running.
- **Never regex-edit code with `|` as the sed/perl delimiter when it contains
  `||`** — it becomes an empty alternation and rewrites every line. Use the
  Edit tool or a python/node patch with literal anchors, then syntax-check.
- `mix run` inside `devenv shell` does not inherit shell variables you set on
  the same command line; write scratch paths into the script instead.
- A 38 MB error dump is what an `inspect` of a checkpoint's params looks like:
  always pass `limit:` when inspecting them.
