## What we learned (in order of importance)

### 1. The live failure is EXPOSURE BIAS, not #81

Measured, not argued. Deterministic live, the multishine policy enters the
grounded reflector and never leaves (97.8% of frames). The decisive number:
in the training fixture action 361 only ever has **af 1..2**; live it sits at
**af 3 through 28**. It operates in states it has never seen, holds B, af
grows, drifts further. Absorbing trap.

This explains everything at once: 99.9% offline (teacher-forced, always
on-manifold); 66 shines when sampling stochastically (random RELEASES kick it
back on-manifold — those shines were noise, not skill); frozen when
deterministic; prev-action didn't help (channel verified active, the STATES
are unseen); af normalization didn't help (2/288 dims).

**Consequence:** 24e's "do NOT spend DAgger rounds on this" was correct GIVEN
the belief that #81 was the cause. That premise is now measured false, so this
IS the coverage case and DAgger is the right tool.

### 2. Phase 2 option 1 works, and buys nothing measurable (yet)

`--live-af` normalizes the bridge's action_frame into the parsed convention.
A/B live, 2 min each vs a level-1 Fox CPU: 66 shines OFF vs 65 ON, median gap
81f vs 83f. Flag verified genuinely wired (embedding tensors change).

Why it can't matter much: the normalization moves **2 of 288 dims** by
1/60 ≈ 0.017. It was never going to flip a policy between a 9-frame chain and
sporadic shines. #81 is real as a data-fidelity bug; it is not this bug.

**Default stays OFF** — not because the work is abandoned, but because at
partial coverage it puts SOME actions in parsed convention and the rest in
live, a mixture matching neither training nor inference. Flip it when coverage
of ENCOUNTERED states is near-total (see task list).

### 3. The action_frame table: 9 → 77 actions, three independent sources

Zero conflicts on any shared action across a Fox TAS loop, a Mewtwo policy vs
a level-9 CPU, and the Fox teacher vs a level-1 CPU. Different characters,
opponents and techniques agreeing exactly ⇒ the convention is a property of
Peppi-vs-libmelee, not of a character. Every delta is 0 or 1.

Coverage of what we actually encounter: **98 distinct states seen, 77 mapped**.
"77 of 399" understates it — 399 counts every character's specials and states
unreachable in normal play.

## New tooling (all committed)

- `scripts/diff_state_streams.exs` + `ExPhil.Eval.StateStreamDiff` — derive the
  parsed↔live mapping from a pair. A valid pair reports **100%** agreement on
  action/on_ground/y; anything less means the halves are different runs.
- `ExPhil.Eval.StateStreamTrace` — emits the LIVE half from the bridge decode
  boundary, so ANY live script records a pair with `EXPHIL_STATE_TRACE=1`
  (`EXPHIL_STATE_TRACE_PORT=N` to pick the port). Skips menu frames.
- `ExPhil.Data.ActionFrameConvention` — the table + `live_to_parsed/2`,
  `known?/1`, `unknown_actions/1`.
- `scripts/eval_policy_on_rollout.exs` — CLOSED-LOOP eval: scores a policy on
  the states it ACTUALLY visits, split on/off the training manifold. Read its
  header before quoting the agreement columns; the off-manifold SHARE is the
  trustworthy number.
- Flags: `--live-af`, `--seconds` (play N then SD to a clean end),
  `--snapshot-every` (dagger_drill), `--dummy-cpu-level` (record_multishine).

## Traps that cost real time today — read before repeating

1. **A timeout-killed run leaves a TRUNCATED .slp** that peppi rejects
   outright ("failed to fill whole buffer"). A 7-minute run was entirely
   unanalyzable. Always `--seconds N` so it SDs to a real game end.
2. **Orphaned Dolphins poison the NEXT run.** Slippi's console port is fixed
   at 51441, so an orphan keeps it and the next run's bridge reads the ORPHAN
   while its pipe drives its own new Dolphin — reading one instance, pressing
   another. Presents as "stuck at MAIN_MENU forever". Kill by matching
   `[A]ppRun.wrapped` (the mounted AppImage), NOT the launcher path.
3. **`pkill -f <pattern>` matches its own command line** and kills the shell.
   Use the bracket trick.
4. **`Agent.get_action/3` returns raw action INDICES**, no `:button_b`. Using
   it for button comparisons silently reads `false` on every frame — two
   different policies then score identically. Use `get_controller/3` +
   `warmup/1`.
5. **record_multishine's DEFAULT mode does not multishine.** `--mode
   multishine` is an open-loop frame script (108 shines, 66-frame gaps);
   `--mode closed_loop` is the real teacher (791 shines, 9-frame gaps, one
   unbroken chain). Header now documents this.
6. **eval_policy_on_fixture.exs flatters memorization policies** — it
   teacher-forces the state channel, so it cannot see exposure bias. It also
   returns near-vacuous scores on fixtures where the reference rarely presses
   B/X (Mewtwo fixtures: 98.5% on one, 82.7% on another, opposite verdicts).
