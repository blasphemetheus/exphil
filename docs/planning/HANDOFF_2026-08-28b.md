## 2. The one lesson worth carrying forward

**Both "null" decode sweeps were MIS-SCORED, not null.**

`coach_report` never measured what the human actually complained about
after the 08-28 play session (taunts, pummel loops, laser dithering), and
the metric it does report — armed approaches/min — is a rare, bursty
event whose own baseline moved **7x across two days**.

Rescoring **85 already-banked replays** on a dense metric — no new games,
no GPU, an afternoon of scripting — turned a dead experiment into a clean
monotone dose-response. `eval_runs/0828_loop_rescore/RESULTS.md`.

The generalizable form: **in this project, instrument work has a far
better return than compute.** The expensive half of an eval (playing the
games) is already banked in `.slp`; a metric added today runs against
every game ever recorded. When an experiment comes back null, suspect the
instrument before believing the null.

**RETRACTION (mine, on the record):** I described the transfer decider as
testing whether the recipe "transfers off Fox" and called it the founding
low-tier goal's only active evidence. **Wrong on both counts.** Both arms
are multishine Fox specialists; what varies is the OPPONENT's character.
It is a shine-line loose end about opponent-character robustness. The
low-tier founding goal (the bot PLAYING Mewtwo/Ganon/etc.) is a different
question and this decider does not bear on it.

## 4. Verified results

### The cost axis is reproducible; the competence axis is not

d_up press/min at buttons T=1.0, four independent sessions:
**430 / 422-495 / 455 / 431.89**. Against `armed/min`, which moved 0.10
vs 0.69 between two of those same sessions. The dense metric can carry an
A/B; the rare one cannot.

Anchored endpoints exist now: the known-bad argmax runs score
frozen-input **0.98-0.99**, every healthy sampled arm **~0.00**, and a
HUMAN presses d_up **0.00/min** (Bradley, 08-28 session, port 2).

### Buttons temperature is a press-rate dial (dose-response)

| buttons T | d_up press/min | ranges |
|---|---|---|
| 0.5 | 112 / 110 | [95-120] / [106-115] |
| 0.6 | 171 / 183 | [157-179] / [164-197] |
| 0.7 | 248 | [237-259] |
| 1.0 | 430 / 432 | [422-450] / [416-454] |

Disjoint, monotone, replicated across two brackets.

**Mechanism** (from reading slippi-ai's code): their buttons are
**Bernoulli**, sticks **Categorical** — and ExPhil's per-head temperature
has the same split. `logits/T` flattens a categorical toward uniform, but
`sigmoid(logit/T)` pulls a Bernoulli toward **0.5** as T rises and toward
**0** as it falls. So for a rare button, temperature is not a diversity
knob, it is close to a direct press-rate dial.

### The dominant pathology, named and counted

`GRAB_WAIT>GRAB_PUMMEL` — 78 / 94 / 16 / 47 episodes across four corpora,
outnumbering every other detected cycle combined. From Bradley's side of
the 08-28 session, `GRABBED>GRAB_PUMMELED` appears 21 times.

**Caveat that must travel with this metric:** raw `loops/min` is NOT a
pathology score. The human "loops" more than the bot (9.64 vs 0.71)
because dash-dancing is a repeated cycle and also correct Melee. Rank by
SPECIFIC pattern, never by the bare count.

## 5. GOTCHA #102 — the harness was deleting the evidence of failure

**Read this one even if you skip the rest.**

`eval_live_protocol.sh` copied each `.slp` out of `~/Slippi` without
waiting for Dolphin to finalize it. Copying mid-flush truncates the file.
**Signature: a page-aligned size (exact multiple of 4096)**; intact files
have arbitrary sizes. 19 of 40 replays in this bracket were unparseable.

**The loss is BIASED, which is what makes it serious.** A game that ends
EARLY (the bot died) gives Dolphin less time to finalize, so per-arm
coverage came out **8/8, 8/8, 4/8, 1/8, 0/8 — perfectly ordered by how
badly the arm played.** `detbtn_hyst` produced ZERO scoreable replays and
was invisible to every replay-based metric in the repo.

A harness with this bug does not add noise; it systematically flatters
bad arms by omitting their failures. **This bracket survived only because
game duration lives in the LOGS.** When a replay-scored comparison looks
odd, cross-check `Final stats: N frames` in the run logs.

Fixed (poll until file size is stable, warn on page-aligned results);
`LoopStats.safe_load/2` skips and COUNTS bad replays; `loop_report` prints
scored/played per arm. **Standing rule: any batch scorer over replays must
report scored/played, not just scored.**

**Unknown and worth someone's attention:** how many past comparisons in
this repo were affected. The bug is old; the bias is invisible in any
result that only reports scored counts.

GOTCHA #103: `Output.config` writes an ANSI reset BETWEEN label and value,
so `grep "Label: value"` cannot match a line that plainly contains it.
Strip ANSI before matching. Cost two false knob-assertion alarms.

## 9. Laws (new this session; the standing ones from 08-28 §7 all hold)

- **Suspect the instrument before believing a null.** Two sweeps, two
  nulls, one metric fix, one clean result — from replays already on disk.
- **Any batch scorer over replays reports scored/played.** Silent
  per-arm coverage differences are indistinguishable from results.
- **Cross-check replay-scored claims against the run LOGS.** Logs
  survived a data-loss bug that destroyed half the replays.
- **A page-aligned `.slp` size means a truncated file.** Never a
  coincidence.
- **Guards should fail loud and safe.** The knob assertion produced two
  false alarms and that is the correct direction for something guarding
  against a silently dropped flag.
- **Do not edit `lib/*.ex` while a multi-stage eval loop is running** —
  each run re-invokes `mix` and would compile your edit into the next
  stage. New `.exs` files the loop does not call are safe.
- **`Code.string_to_quoted!` parse-checks a script without `mix`**, which
  is the only syntax check available while a beam is live.
