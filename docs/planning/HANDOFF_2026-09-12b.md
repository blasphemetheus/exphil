## 3. Standing rules (new ones first)

- **Controls first, always.** Before reading a policy number out of any
  harness, run a control the policy is KNOWN to pass (its own replay)
  and sweep the latency knob. A memoryless teacher passing proves
  nothing about the harness rung. A chain that re-enters then floats is
  a timing-convention bug until a control excludes it.
- **A chain optimum is not a latency measurement.** Only a recorded
  marker is (`LatencyProbe` vs the .slp).
- **Delayed labels come from the label source's own future** (item 14).
  Never `shift_actions` an expert-labeled list; the code refuses.
- **The pool auditor runs AT the training shifts and gates every
  prereg** (`--shifts` = the drill's `--multi-delay`).
- **Verify offline before Dolphin:** the coverage map is 5 minutes.
  Then BOTH live numbers must hold (stand floor = technique, CPU gate =
  coverage) — g24a/g25a showed one rises while the other falls.
- Older: never crown on stand-dummy numbers (g6); sampled gates (T=1.0),
  never argmax; `mix` never while a beam is live; long runs via
  `systemd-run --user`; no bespoke decode rules.
