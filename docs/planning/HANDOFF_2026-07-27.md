## Where the work stands

**Root cause: exposure bias.** The policy trains on one trajectory; one frame
of timing slip lands it in grounded reflector (361) at `action_frame` 3..28,
which training never contains (fixture has af 1..14). It holds B, af grows, it
drifts further. 97.8% of frames stuck in one action. See GOTCHAS #81 "ROOT
CAUSE FOUND".

**One intervention works, and it is large.** `ExPhil.Data.RecoverySynth`
manufactures those off-trajectory states and labels them with
`MultishineExpert`'s EXISTING recovery rules — rules that were only ever
executed live, never trained on.

| | self-initiated shines/min | max chain |
|---|---|---|
| baseline | 11.4 · 3.0 · 5.2 | 1 · 1 · 1 |
| **synth** | **58.4 · 36.2 · 29.4** | **5 · 3 · 6** |

Baselines NEVER chain (max 1). Synth policies do. Cost: seconds to synthesise,
~2 min to train, no GPU, no Dolphin, no rollouts.

**Ruled out or unmeasurable:** af-convention normalisation (2/288 dims, no live
effect, model later proven invalid — GOTCHAS #81 "SETTLED"), prev-action
channel, noise injection. The last two landed inside synth's own spread.

## THE NEXT STEP — run the perturbation harness

Built, committed, **never run**. `record_multishine.exs` gains `PERTURB_EVERY`
/ `PERTURB_FRAMES`: every N frames it feeds the teacher random inputs for M
frames, knocking it off-trajectory, then hands control straight back so it
plays a REAL recovery. Slippi records the session; `dagger_drill.exs` relabels
it offline.

Why it matters: `RecoverySynth` can only EXTEND segments the fixture already
visits, and its labels are only as good as the recovery rules. The teacher
holds 791 unbroken cycles — perturbing it yields ground-truth recoveries from
states synthesis cannot reach.

    # record (teacher, closed loop, real level-1 CPU, graceful end)
    PERTURB_EVERY=180 PERTURB_FRAMES=6 \
      mix run scripts/record_multishine.exs --mode closed_loop --seconds 120 \
        --dummy cpu --dummy-cpu-level 1 --out /tmp/perturb1.slp

    # relabel into training data
    mix run scripts/dagger_drill.exs --expert multishine \
      --rollouts /tmp/perturb1.slp --out checkpoints/ms_perturb.bin \
      --snapshot-every 2

**`--mode closed_loop` is mandatory.** The DEFAULT `multishine` mode is an
open-loop frame script that does NOT hold the loop (108 shines at 66-frame
gaps vs 791 at 9).

**`--out` defaults to `test/fixtures/replays/fox_multishine.slp`** — a COMMITTED
fixture. Always pass it explicitly.

## READ THIS BEFORE MEASURING ANYTHING

**The variance is in the RUNS, not the training seeds.** Four live runs of ONE
fixed policy: 58.4 / 26.9 / 40.2 / 34.2 self-shines/min — a 2.2x spread with
the network held constant.

Every comparison before 07-27 trained ~3 seeds and did ONE run each, i.e. n=1
on the dimension that actually varies. That is why prev-action and noise came
back null — underpowered design, not absent effects.

**Protocol:**

1. **≥3 live RUNS per policy.** More important than seed count.
2. A run is ~4 min, a training ~2 min — three runs of one policy beats three
   policies of one run at similar cost.
3. Score with `scripts/analyze_shine_source.exs`: self-initiated shines and max
   chain. NOT the off-manifold agreement metric (44-77% noise at one config).
4. Report mean and range. A difference under ~2x is not resolvable.
5. Rate and chain length do NOT track each other — report both.

## Known traps (each cost real time)

- **The opponent interferes with the measurement.** Bradley observed the
  level-1 CPU walking up to jab (interrupting a multishine) and lasering
  (causing shine lag). `analyze_shine_source.exs` already splits
  self-initiated from hit-induced shines for this reason, but for a CLEAN
  capability measurement consider an idle opponent instead — ironically the
  "broken" HUMAN dummy of GOTCHAS #57b is the better control here, since it
  cannot reach you.
- **Dummy CPU setup was silently not a CPU** until 07-26 (5 of 6 runs came up
  `type=HUMAN`). Fixed by gating autostart on the CPU being configured. Verify
  any recording with `mix run scripts/check_replay_ports.exs <slp>
  --expect-cpu 2`.
- **A killed run leaves a TRUNCATED .slp** peppi rejects outright. Always use
  `--seconds N` so the game ends properly. SD now runs INSIDE the frame loop
  (4/4 finalized, was ~70%); `scripts/record_until_valid.sh` retries as
  belt-and-braces.
- **Orphaned Dolphins poison the NEXT run** — Slippi's console port is fixed at
  51441, so an orphan keeps it and the next run reads the ORPHAN while driving
  its own instance. Presents as "stuck at MAIN_MENU forever". Kill by matching
  `[A]ppRun.wrapped` (the mounted AppImage), never the launcher path, and never
  with a `pkill -f` pattern that also matches your own command line.
- **`Agent.get_action/3` returns raw indices**, no `:button_b`. Use
  `get_controller/3` + `warmup/1` for anything comparing buttons.
