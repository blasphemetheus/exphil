## Queue-as-input state (the day's build)

- **Architecture COMPLETE and verified end-to-end**: embedding channel
  (`queue_depth` K slots + `with_delay_id` one-hot 9; K=1 ==
  classic prev-action, pinned byte-identical), data pipeline (per-slot
  boundary/dropout/DAgger conventions; DAgger slots read
  `frames[i-k+1].prev_controller` so expert corrections never leak),
  live agent ring buffer + `delay_id` (from --frame-delay), export/load
  carry the layout (flat config keys; the embed_config map is a legacy
  flattened thing that drops unknown keys — export whitelist is in
  `imitation/checkpoint.ex`). Tests: `test/exphil/training/queue_input_test.exs`.
- **Two config structs exist** (%Embeddings.Game{} AND %Game.Config{});
  datasets carry the former. New embed fields go in BOTH (learned hard).
- **Live-queue forensics instrument**: `EXPHIL_QUEUE_TRACE=1` on any
  play script logs per-frame ring contents + GAME-APPLIED inputs
  (`applied=` from libmelee controller_state — replay-free ground
  truth). Verdict: decode->send->apply chain is PERFECT (100.0%
  agreement); live decision->application latency at --frame-delay N is
  **N+2** (the intrinsic +2, now measured input-side). Under the correct
  frame correspondence the queue indexing was right; the LABEL shift is
  what should be N+2 (`--pipeline-offset 2`).
- **queue1 lesson**: teacher-forced queue channels amplify exposure
  bias (58-73/min vs control's 239/99/95 despite 3x lower loss).
  Mitigation BUILT 2026-07-31 evening: **SS-on-queue** — ScheduledSampling
  now self-samples all K queue slots (slot k = model's decoded prediction
  on the window truncated by k; exact under any shift mix since slots are
  built from shifted frames). ss_queue_depth auto-derives from the
  dataset embed config; existing `--scheduled-sampling P --ss-ramp N`
  flags just work. The broken backend-mixing test is fixed (the fake
