## 2. The headline result (fox_gen_v1)

Trained: GRU-60, stride 5, batch 256, f32, lr 1e-4 constant,
`--stage-internals` (296-dim embedding), 10 epochs, ~11.4h. Val
6.639 → 5.789 monotonic. Full detail:
`eval_runs/0826_gen_v1_sweep/RESULTS.md`.

**Live, 30 games vs CPU at temperature 0.5 (quiet machine):**
- 0.50 armed approaches/min
- **35/100 conversions (35%)**
- 1.7 deaths per 2-minute game

For scale, the drill-era Mewtwo that motivated GOALS.md's Track A
gates managed 0.17 approaches/min and 5% conversion. (Different
character and opponent tier — not apples-to-apples, but suggestive.)

### The discovery: decode strategy, not training, was the difference

Same checkpoint, same quiet machine:

| decode | result |
|---|---|
| argmax (`--deterministic`) | dead in ~32s, 4 SDs, 0 conversions — "crouches, then runs off the stage four times" |
| temperature 0.3 | survives, does almost nothing |
| **temperature 0.5** | full repertoire: grabs, lasers, shines, rolls, throws, up-B to ledge, shine-wavedash, short-hop drilling |

**A RETRACTED DIAGNOSIS, on the record:** overnight I attributed the
crouching to harness starvation (a CPU-heavy job was pinning the
machine and live runs showed 51% stale input sends). That was WRONG.
The clean argmax run had **0.0% staleness and still crouched and
SD'd**. Starvation was real and did corrupt those particular runs, but
it was not the cause of the behavior. Mode collapse was. Don't let a
plausible confound close an investigation.

### Why argmax collapses (mechanism, measured)

The model is a population BC model: at most decision points it holds a
genuinely multi-modal distribution. Argmax picks the marginal winner,
which in Melee skews toward "keep holding what you're holding."
Interp confirmed the mechanism — see §3.

## 3. Interpretability results (INTERP_GEN_V1)

Doc: `docs/planning/INTERP_GEN_V1.md` (program G1–G7 + results ledger).
Two instruments have run; both are cheap and repeatable.

**G1 — entropy by situation** (`scripts/interp_entropy_map.exs`,
output `eval_runs/0826_gen_v1_sweep/entropy_map.txt`):
- Heads live in different entropy regimes: buttons at **69% of
  uniform**, main sticks 48%, c-stick 25%, shoulder 41%. **A single
  global temperature is the wrong shape — per-head temperature is a
  correction, not a tweak.**
- Entropy tracks real game sense (a soundness check it passed):
  lowest on `edge_danger`, `tumble`, `shine_cancellable` (main_y 0.91
  — the model knows which way to hold); highest on
  `pummel_throw_decision`, `being_tech_chased`, `walltech_available`,
  `shield_pressure_theirs`.
- `disadvantage`/`in_hitstun` ≫ `advantage`/`combo_active` → defense
  is the thin-supervision pocket (curation target for v2).
- `neutral` < `conversion_open` → **the weakness is finishing, not
  entering** (matches 9–13 dropped punishes per epoch in the sweep).

**G2 — history-vs-state dominance**
(`scripts/interp_history_dominance.exs`):
- HISTORY/CURRENT ratio **0.391** — the current frame moves the output
  distribution ~2.6x more than 50 frames of history.
- Frozen-tile stay-mass: idle 0.202 vs active 0.208 → **no idle
  stickiness.**
- **Verdict: exposure bias is NOT structural.** v2 does **not** need
  scheduled sampling (it would solve a problem this model lacks), and
  the crouch loop is confirmed decode-side, not memory-side.

**Combined:** the model contains the behavior and holds appropriate
uncertainty; what it lacks is a **selection rule** over its
distribution. That is the evidence-backed case for the value model.

## 5. Hard-won operational laws (violating these costs hours)

- **NO-MIX LAW.** Any `mix` invocation beside a live training/eval
  beam recompiles EXLA's NIF and SIGSEGVs it. Check
  `pgrep -f "[p]lay_dolphin"` / `pgrep -c beam.smp` first. Run mix via
  `devenv shell -- mix ...` **from the repo root**.
- **Long runs need `systemd-run --user`.** Anything launched from the
  agent's Bash tool — foreground, background, even `setsid` — gets
  SIGTERM'd at ~10 minutes. Pattern that works:
  `systemd-run --user --unit=NAME --working-directory=/home/blewf/git/exphil --collect -p StandardOutput=append:LOG -p StandardError=append:LOG devenv shell -- <cmd>`
  (needs `dangerouslyDisableSandbox: true`). tmux is NOT installed
  system-wide. Manage with `systemctl --user status|stop NAME`.
- **Live evals are invalid on a loaded machine.** Check loadavg and
  the staleness line in run logs before believing any live number.
- **Never `2>/dev/null` a long-running script's output.** Cost an hour
  here (a sweep reported "FAILED" ten times with the reason
  suppressed). Tee to a log; read the log.
- **Deterministic decode is not neutral.** It is a strong intervention
  that can invert a policy's behavior. Always record which decode an
  eval used.
- **`command` prefix for coreutils in Bash** (the user's shell aliases
  them to rust replacements). Python only for the libmelee bridge and
  frame-data tooling, never for file edits.
- Chains are scored from `.slp` replays only, never press counts.

## 6. Statistics warning (read before ranking anything)

The 10-epoch live sweep in `RESULTS.md` **cannot rank epochs and must
not be read as ranking them.** Within-epoch spread equals
between-epoch spread (ep4: 0.0/0.98/0.0), n=3 games. The standing
project law is that **differences under 2x are unresolved**. ep10's
eye-catching 70% conversion is one lucky game.

Corollary worth internalizing: **epoch 1 already played** (0.49
approaches/min, 29% conversion). Ten epochs of val-loss improvement
bought no visible behavior change — and val loss ANTI-correlates with
behavior in this project's history. Rank by behavior, at adequate n,
or don't rank.
