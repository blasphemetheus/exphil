**Step 1 — blocking input + polling mode (engineering, derisked):**
- `blocking_input`: Dolphin waits for the bot's controller write each
  frame (the game CANNOT outrun inference). slippi-ai:
  `slippi_ai/dolphin.py:298` (`DolphinConfig.blocking_input=True`),
  plumbed at `:132` to Dolphin's ini. Check libmelee's Console/ini
  support in our vendored version; wire through
  `priv/python/melee_bridge.py` init (config keys around lines
  282-313, where online_delay already plumbs).
- Polling mode: `Console(polling_mode=...)`/`console_timeout`
  (slippi-ai `dolphin.py:134`) — console.step returns None on no-frame
  instead of blocking forever. Bridge's single-threaded command loop
  (melee_bridge.py main, ~line 1020) must handle None-step. UNBLOCKS
  LRAS (flip @lras_frames to 120 in async_runner.ex + play_dolphin.exs;
  quit sequence needs L+R+A held with Start PULSED — a fresh Start edge
  on the pause screen; continuous hold never re-edges).
- Validation: sync eval block with blocking input — skip stat must stay
  0 AND offset calibration on its replays should collapse to ONE clean
  peak (the variable-jitter evidence was calibration max 0.67 spread
  over offsets; blocking input should push one offset >0.9).

**Step 2 — stateful O(1) inference with bit-parity gate:**
- Edifice.Stateful step path exists (play scripts print "Stateful:
  Edifice.Stateful step path (O(1)/frame)" when enabled); the GRU
  policy currently re-encodes the 16-frame window every frame.
- slippi-ai's discipline: training unroll and deployment step are the
  SAME function under scan — no train/deploy divergence possible.
- Gate (write FIRST): bit-parity test — stateful step vs window
  re-encode on fixture-replay windows, logits identical (tolerance ~0;
  embed_path_parity_test is the prior art for this bug class).
- Payoff: ~16x less per-frame compute; removes a divergence class;
  required shape for netplay-scale models.
