Decode

Buttons temperature is a press-rate dial, not a diversity knob

d-up presses/min: T 0.5 → 112 · 0.6 → 171 · 0.7 → 248 · 1.0 → 430. Monotone, disjoint ranges, two brackets. Mechanism: buttons are Bernoulli — sigmoid(logit/T) pushes a rare button toward 0 as T falls, whereas sticks are categorical and merely sharpen. Deaths rise as buttons cool (1.1 → 1.6 → 2.0 → 4.0); T=0.5 is next to the cliff.

Directions

Bradley's standing direction: exhaust v1 (retrain-free first) before v2; delay is a later generation; v1 and v2 stay local-only. "Exhausted" = when the triad says selection is no longer the biggest number.

A · Keep tuning v1 decode

Near its end
What
The rule that turns per-frame probabilities into a press. Zero training cost, minutes per try.
Left
Per-button temperatures (cool only d-up and Z, not A/L/X) — targets the two named pathologies without taxing follow-ups. One more bracket, then stop.
Why not more
Deaths climb as buttons cool; the knob has a cliff and T=0.5 sits beside it. Local optimum, not a road.

B · A critic (value model) → Best-of-N

Needs a tail-keeping selector
What
A second network scoring candidates; decode becomes sample N, score, pick. Still the selection rule v1 lacks — but today showed the obvious versions of it pick the mode, and the mode freezes the bot.
Ran
Linear V(s) + bilinear selector on trunk ⊕ raw scalars (eval_runs/0829_critic): 27% of the gap held-out, controls clean, lost to majority vote (19.0 vs 22.9 pass@1). V(s) ranks states above chance (0.60 vs 0.51) but explains 5% of return variance.
Gate
Any selector must beat 22.9 / 6.8 offline AND pass the live gate (frozen-input ≤ 0.20, 7/8 to cap, deaths ≤ 1.5×). Offline is now the easy half. An MLP head is not queued until there is a reason to believe it keeps the tail.

C · AWBC arms B1/B2/B3

Null
What
Re-weight BC frames by actual game outcome (return-to-go). Same network, different loss weights; 3 epochs each from ep10.
Result
8 games per arm, same protocol, same day: max ratio 1.5× on any pathology metric, every range overlapping, deaths 2.4 / 2.0 / 1.5 (overlapping). Val loss moved (B2 lowest), play did not — the ep1..ep10 decoupling again. eval_runs/0828_awbc_arms/RESULTS.md.
Left
One sharper-β arm is allowed by the prereg; deferred — it would still only reweight the master's choices, and the gap is in the bot's own picks.

D · fox_gen_v2

Not yet
What
New recipe / size / corpus. The competing story: 3M params on ~90M frames with val-loss still falling is textbook underfit.
Gate
Leg S. If pass@16 ≈ pass@1 both low, no selector can help and capacity or data is the ceiling — then and only then v2.

E · Interp-guided fixes

Opportunistic
What
Locate why the pummel loop fires (a saturating grab feature?) and patch by curation, decode masks, or drills.
Payoff
Highest curiosity, least predictable. Ride it when a probe result falls out of B.

Where this leaves the program. Leg S is calibrated and real: the master's action is in the sampled set far more often than it is played, at every epoch. But every selector tried today that concentrates the decode — outcome weights, a learned ranker, a majority vote — either did nothing or reproduced the argmax collapse. The headroom is a fact about the distribution; cashing it needs a rule that keeps the distribution's tail while moving its center, and no candidate for that rule exists yet. Do not start v2 on this evidence (capacity is still not the biggest number), and do not spend more decode brackets on mode-seeking ideas.

Concrete next candidates, cheapest first: (1) Leg S at T→0 to formally show argmax wins the offline metric (running); (2) a selector scored by a state value after a short CycleSim rollout rather than by master-match, since V(s) ranks above chance; (3) direction E — find why the pummel loop fires and mask it, which changes picks without collapsing them.

Laws

Standing rules that earned their place by costing something. The older ones (never crown on stand-dummy numbers, pin stages in deciders, chains from ShineChain over replays only) still hold.

L1Suspect the instrument before believing a null. Two sweeps, two nulls, one metric fix, one clean result — from replays already on disk.
L2Any batch scorer over replays reports scored/played. Silent coverage differences are indistinguishable from results.
L3Cross-check replay-scored claims against the run logs. Logs survived a bug that destroyed half the replays.
L4A page-aligned .slp size means a truncated file. Never a coincidence.
L5Mechanism metrics can move while the event doesn't. A 4.5× cut in d-up presses left taunt entries flat. Keep the human-gated rung.
L6Never launch netplay without the bot account. The script now enforces it; the DEPLOY_KNOBS row was the dropped flag.
L7No lib/*.ex edits while a multi-stage loop runs; Code.string_to_quoted! is the only syntax check while a beam is live.
L8Long runs go through systemd-run --user. The Bash tool SIGTERMs everything at ~10 min; tmux is absent on slanka.
L9Offline master-match is mode-seeking and cannot rank decodes alone. Mode-of-16 won it by +8 pts and froze the bot live. Every decode metric is paired with frozen-input, duration, and deaths from a live bracket.
L10An embed-layout flag must reach every embedding path. --stage-internals reached the checkpoint and the Agent but not Activations; every trunk capture of v1 died 288-vs-296 until it did (GOTCHA #105). Grep for with_delay_id when adding one.
