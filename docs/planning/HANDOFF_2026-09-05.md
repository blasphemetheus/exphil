## 4. Findings and decisions this session (git messages carry the rest)

   (EXPHIL_BPTT_PROFILE=1) showed 98.5% of each 1.9-3s step was
   `TrajectoryCursors.next_batch` slicing the chunk embedding at 128
   varying offsets: eager EXLA compiles ONE executable PER DISTINCT
   slice start → ~128 XLA recompiles/batch. The jitted train step was
   18.6ms all along. Fix = one `Nx.take` gather (offsets as runtime
   data) → ~30ms/step ≈ 337k frames/s (~100x). Loss trajectory
   identical at seed 905. GOTCHA #112. Batch-size-invariant throughput
   was the tell that got misread as "sequential unroll dominates."

   migration — `native_impl?` false meant every "fused" scan ran

## 5. Gotchas / operational law (new; older in HANDOFF_2026-09-04 §5, GOTCHAS.md #108-112)

- **GOTCHA #112** (in GOTCHAS.md): eager EXLA ops recompile per
  distinct constant (slice starts!). Per-step hot paths may vary only
  tensor CONTENTS. Profile the LOOP before the GRAPH —
  `EXPHIL_BPTT_PROFILE=1` exists for exactly this.
- **EDIFICE_FUSED_CUSTOM_CALL=1 is the master switch** for the fused
  tier. Without it: byte-identical legacy behavior. With it but
  WITHOUT the kernel-linked libexla.so: any gru/mamba graph FAILS at
  XLA compile (unknown custom-call target) — that's deliberate
  (loud). The defimpl is f32-only; bf16 silently :skips to fallback.
- **Archive extraction inflates ~4x** (7z on .slp): 18G of yeti
  archives → 69G+, which filled / to 0 mid-session (v15full survived
  only because the ENOSPC window fell between checkpoint saves).
  Budget before extracting; extract *.slp members only.
- **`Nx.backend_transfer` DELETES the device buffer** (it moves);
  use `backend_copy` when the tensor is still needed on-GPU. Bit us
  as phantom "Buffer has been deleted or donated" errors.
- **Nx.Defn.jit caches per anonymous-fn DEFINITION SITE** — A/B-ing
  tiers by re-invoking the same fn under a flag reuses the cached
  executable. Use two textually distinct fns.
- **Mamba's selective_scan fallback IGNORES its A argument**
  (hardcodes -(1..S)); the kernel honors A. They agree only for the
  canonical A mamba passes. Kernel state limit: S<=32, silent
  truncation beyond — defimpl guards it.
- The progress bar's s/it + ETA are now ROLLING (anchors from batch 1,
  window 100): they exclude first-batch JIT but INCLUDE amortized
  chunk parse stalls. The batch-100 "estimated training time" line
  excludes per-chunk parse/embed entirely (labeled as such).
- Bash-tool commands still die at ~10 min (SIGTERM) — the yeti
  extraction died to this once; anything long goes through
  `systemd-run --user` (dolphin evals excepted: foreground only).
