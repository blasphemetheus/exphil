# Zero-state/F32 bounded multishine proof

Purpose: demonstrate that the local training/harness pipeline can learn repeated
multishines and recovery. No separate teacher-model distillation: recorded expert
actions already supply the supervised targets, and the previous model has known
mistakes we should not teach to the new model.

## Frozen protocol

- Fresh GRU64, two layers, AR head, window16, queue3, cold histories, delay2.
- `windowed_gru_f32_v1`: zero initial hidden state for every window, F32 throughout.
- Save the exact fresh initialization before any optimizer update. No old weights,
  resume, distillation anchor, architecture sweep, or training-budget extension.
- Same 7,785 targets. First18 recorded targets repeated x64: 14,589 draws and
  228 batches/epoch. Fixed budget: **21 epochs / 4,788 updates**.
- Select ordinary best aggregate training loss, not a hand-picked epoch.
- Unweighted six-case early gate: each first18 target correct and joint probability
  >=0.95. Only a passing checkpoint advances to the unchanged matched-teacher
  12-response live gate: valid timing, no errors/drift, chain>=10 in every response.

## Next narrow task

Inspect the two remaining misses against the actual training inputs before more
optimization. In particular, the inherited drill recipe uses **0.1 previous-action
dropout during embedding precomputation**, while the fixed evaluator uses0.0.
That is an intentional augmentation but can make a tiny memorization proof's
training inputs differ from its evaluation inputs. It is a hypothesis to test,
not a confirmed explanation of these errors. The previous window comparison
reconstructed windows without this stochastic augmentation.

For a minimal pipeline proof, prefer a controlled no-augmentation fit if that
audit confirms the difference matters. Do not add distillation, widen the model,
or relax readiness thresholds to compensate. Then run matched-teacher local
closed-loop validation on the same qualified checkpoint.
